## Executive Summary

**Overall Health:** CRITICAL &nbsp;|&nbsp; **Deployment Confidence:** LOW

**Dominant Risk Themes:** Critical injection and path-traversal flaws in backend code, Hardcoded secrets exposed in repository and container images, Widespread vulnerable dependencies requiring immediate upgrades, Deployed workloads violate Kubernetes security policies systemically, Infrastructure-as-code grants excessive IAM permissions and open firewall rules, Container image signatures cannot be verified; supply chain broken

This release exhibits critical-severity defects across every security domain. At the application layer, sonarcloud and codeql identify command injection (S2076), OS command construction from user input (S2083), XSS (S5131/S5696), and hardcoded credentials (secrets:S6698, S2068, gitguardian findings)—these are present in source files and reproducible. Frontend axios (0.21.1) carries 28 CVEs and dompurify (2.3.3) carries 20+ CVEs, nearly all fixable by upgrading. Backend containers load 57 vulnerable OS packages (expat, gnutls28, krb5, openssl, zlib) at critical and high severity; OS upgrades are available. Infrastructure-as-code grants project-level Owner roles to compute service accounts, exposes SSH/RDP/MySQL to 0.0.0.0/0, and disables logging/monitoring. Deployed workloads fail 9 out of 11 default security policies: privilege escalation (20+ occurrences), unsigned images, missing seccomp, running as root (20+ occurrences), and missing resource limits. Runtime security (ZAP) reports missing HTTP security headers. Supply chain verification is broken: both images return MANIFEST_UNKNOWN, preventing signature validation. The combination of exploitable application code, known-vulnerable dependencies, policy violations at runtime, and infrastructure misconfigurations makes this release unsuitable for production without major remediation.

## Cross-Domain Analysis

### Application injection flaws paired with overpermissive infrastructure and missing network controls

**Affected domains:** application_security, infrastructure_security, runtime_security &nbsp;|&nbsp; **Confidence:** HIGH

Critical injection vulnerabilities in backend (688d20fa838a: S2076 command injection, 447335a06a0f: S2083 path-traversal, 757685f73438: SQL injection) are amplified by infrastructure that binds the service to all interfaces (98cbea7df317: S8392 network exposure) and firewall rules permitting unrestricted access from 0.0.0.0/0 (57df84a4027d, dbbdc1cf61c2, 3ba928b4fd97, 382c6fe86e55, e5f32d7b4723, be6a83a66fe7). An attacker exploiting the injection flaws gains unfettered network access to the backend without geographic or source restriction.

**Business impact:** An attacker can exploit injection flaws to execute arbitrary OS commands or traverse the filesystem, and the wide-open network perimeter means this exploitation is trivial from any network location without additional infrastructure compromise.

**Recommended action:** Immediately restrict ingress firewall rules to known CIDR blocks; remediate injection flaws in source; deploy network policies to segment workload-to-workload traffic.

**Evidence:** `688d20fa838a` (pythonsecurity:S2076, CRITICAL); `447335a06a0f` (pythonsecurity:S2083, CRITICAL); `757685f73438` (py/sql-injection, MEDIUM); `98cbea7df317` (python:S8392, CRITICAL); `57df84a4027d` (CKV_GCP_3, CRITICAL); `dbbdc1cf61c2` (CKV_GCP_2, CRITICAL); `3ba928b4fd97` (CKV_GCP_88, CRITICAL)

### Hardcoded secrets in source code compounded by unsigned container images and no supply chain verification

**Affected domains:** application_security, supply_chain, runtime_security &nbsp;|&nbsp; **Confidence:** HIGH

Multiple hardcoded credentials (049991827bea: PostgreSQL password, ba3dc970c4bd: SECRET_KEY, 00af2baa5ff3 & 45577584570d & 0ad3628d28ea: gitguardian findings) are committed to the repository and baked into container images. The same images cannot be verified as signed (backend/frontend both return UNKNOWN verification_status). **Evidence:** `049991827bea` (secrets:S6698, CRITICAL); `ba3dc970c4bd` (python:S2068, MEDIUM); `00af2baa5ff3` (Username Password, MEDIUM); `45577584570d` (Generic Password, MEDIUM); `f84f2db980d4` (verify-image-cosign/verify-cosign-keyless-signature, CRITICAL); `3f6606939177` (verify-image-cosign/autogen-verify-cosign-keyless-signature, CRITICAL)

### Vulnerable frontend dependencies paired with missing HTTP security headers and XSS vulnerabilities

**Affected domains:** application_security, runtime_security &nbsp;|&nbsp; **Confidence:** HIGH

Frontend axios (0.21.1) carries 28 CVEs, many involving SSRF and prototype pollution; dompurify (2.3.3) carries 20+ CVEs including XSS and template injection (82d7f2881d4c, 6751a218019c). These libraries are used to fetch data and sanitize user input, but security headers (CSP, X-Frame-Options, X-Content-Type-Options, HSTS) are missing at runtime (7bee09ed010a, c2b6922903f8, 43184d5b328f). An attacker can exploit SSRF in axios to access internal services, bypass dompurify's weak sanitization to inject malicious scripts, and use the absence of CSP to exfiltrate data or execute cross-origin attacks.

**Business impact:** Users' browsers are vulnerable to XSS, CSRF, and SSRF attacks. Attacker can steal credentials, redirect users, or pivot to internal APIs exposed to the frontend.

**Recommended action:** Upgrade axios to >=0.31.1 (frontend) and dompurify to >=3.4.12 immediately. Add Content-Security-Policy, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, and Strict-Transport-Security headers at the reverse proxy or application level.

**Evidence:** `0dc16d7ed2e9` (SNYK-JS-AXIOS-16298058, CRITICAL); `a7b165255456` (SNYK-JS-AXIOS-16299904, CRITICAL); `82d7f2881d4c` (SNYK-JS-DOMPURIFY-8318045, CRITICAL); `6751a218019c` (jssecurity:S5696, CRITICAL); `7bee09ed010a` (10038-1, MEDIUM); `c2b6922903f8` (10020-1, MEDIUM); `43184d5b328f` (10021, LOW)

### Deployed workloads violate Kubernetes security policies; privilege escalation, unsigned images, and missing seccomp

**Affected domains:** runtime_security, container_security &nbsp;|&nbsp; **Confidence:** HIGH

Kyverno policy checks reveal systematic violations: privilege escalation is allowed (f913039e3a2a, 73e307bc47c2: 20+ occurrences), no seccomp profile is set (1a438da1f2bb, b5041d14c6bd: 20+ occurrences), containers run as root (55a0910c0cd3, 79abedf3ae77: 20+ occurrences), and images lack content-digest verification (f84f2db980d4, 3f6606939177). Capabilities are not dropped (e9fffb850fa8, 448a793445e1: 20+ occurrences). Together, these enable privilege escalation from a compromised workload to cluster-admin or to escape the container entirely.

**Business impact:** A vulnerability in any workload (or a malicious injected image) can escalate to break out of the container, compromise the cluster control plane, or access secrets from other namespaces.

**Recommended action:** For all deployments: set `allowPrivilegeEscalation: false`, `runAsNonRoot: true` with non-zero `runAsUser`, `seccompProfile.type: RuntimeDefault`, `capabilities.drop: [ALL]`, `readOnlyRootFilesystem: true`. Enforce these via Kyverno 'audit' mode, then 'enforce' mode.

**Evidence:** `f913039e3a2a` (disallow-privilege-escalation/privilege-escalation, CRITICAL); `73e307bc47c2` (disallow-privilege-escalation/autogen-privilege-escalation, CRITICAL); `1a438da1f2bb` (restrict-seccomp-strict/check-seccomp-strict, HIGH); `b5041d14c6bd` (restrict-seccomp-strict/autogen-check-seccomp-strict, HIGH); `55a0910c0cd3` (require-run-as-nonroot/run-as-non-root, HIGH); `79abedf3ae77` (require-run-as-nonroot/autogen-run-as-non-root, HIGH); `e9fffb850fa8` (disallow-capabilities-strict/require-drop-all, HIGH); `f84f2db980d4` (verify-image-cosign/verify-cosign-keyless-signature, CRITICAL)

### Risk 1: Critical OS command injection in backend (S2076)

**Confidence:** HIGH

**Impact:** Remote code execution as the application user (typically root in this image)

**Why it matters:** This is exploitable by any authenticated user sending a request with a crafted payload. The backend is exposed to the internet via firewall (0.0.0.0/0) and permissive network policies.

**Recommended action:** Immediately apply input validation to the parameter passed to os.system() or similar; refactor to use a safe subprocess library with list-style arguments (no shell=True). Backport to the current release and patch in-place.

**Evidence:** `688d20fa838a` (pythonsecurity:S2076, CRITICAL)

### Risk 2: Critical path-traversal flaws in backend (S2083, py/path-injection)

**Confidence:** HIGH

**Impact:** Arbitrary file read/write on the container filesystem; potential privilege escalation if sensitive files are targeted

**Why it matters:** Occurs 4 times across two different tools (sonarcloud, codeql); indicates systemic lack of path validation, not a one-off bug.

**Recommended action:** Audit all user-supplied path parameters. Implement a path allowlist and os.path.abspath() / pathlib.Path.resolve() check to confirm the resolved path stays within an intended base directory.

**Evidence:** `447335a06a0f` (pythonsecurity:S2083, CRITICAL); `9de17c0300aa` (py/path-injection, MEDIUM)
